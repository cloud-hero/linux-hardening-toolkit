# Public toolkit distribution · LH-1.4

This repository is the curated toolkit built and validated in the CloudHero Linux hardening workspace. LH-1.4 adds optional public vulnerability context on a macOS/Linux analysis workstation: an operator runs the Python 3.10+ standard-library helper to snapshot Cloudflare Zero Wire RSS and CISA KEV, then supplies normalized context to the assessment prompt. The article, PDF and README link Cloudflare's 3 November 2026 announcement. The prompt requires official vendor verification before conclusions and keeps vulnerability findings in an unscored appendix.

The helper neither reads server evidence nor connects to a target. Online fetch and offline normalization are distinct commands. Source times, hashes and failures remain visible; a missing KEV source yields unavailable, not not_listed. A successful fetch is not a security PASS. Embedded briefing prompts are omitted and source summaries remain untrusted. Public advisory research by the model requires explicit operator allowance; offline analysis is the default.

The required workflow remains operator collection on the server, redaction and approved transfer, then prompt-based analysis on a different machine against supplied evidence. Assessment, separately approved hardening changes and optional disposable-lab reproduction remain separate guides. Server collection, inventory/report tools, lab fixtures, executable hardening instructions and the 28-control LH-1.2 catalogue are unchanged. The worked report remains 3 scoped PASS and 25 MANUAL.

Validation includes 19 offline intelligence fixtures (source failures, input integrity, parser limits, unsafe redirects, embedded instructions, file permissions and exact replay), the existing inventory/report/guide suites, publication checksums and the packaged ZIP. A live public fetch on 5 November 2026 returned six briefings and eight candidate CVEs with both sources parsed; offline normalization reproduced the exact context bytes. The dated receipt in evidence/intelligence-validation-lh-1.4.json records source hashes and timestamps. These transient counts are observations, not expectations for later runs. Raw public feeds remain outside this distribution.

The PDF is the rebuilt, visually reviewed 20-page LH-1.4 assessment edition. Article content, links, copy targets and generated artifacts passed local checks. Interactive Chrome validation was unavailable for this edition because the computer-use surface could not find an accessible browser window. The page remains a local preview pending explicit website release approval. No website deployment or new VM run is claimed. The historical VM tests remain dated as originally recorded; this release adds only workstation functionality. Normal workstation tests retain the root-only capture-test skip. Prompt instructions are not a security sandbox; the operator must enforce the execution boundary.

The source website and VM runtime are not part of this repository. No VM disks, private keys, credentials, raw application logs, local browser screenshots or runtime state are included. Historical transcripts describe a disposable lab; usernames, private-range lab addresses, kernel versions and timestamps are lab observations, not production targets or current recommendations.

`evidence/source-sha256.txt` is the original build's historical source manifest. It includes builder files outside this curated distribution and is not a checksum list for this repository. Root `SHA256SUMS` covers this published distribution, excluding itself. Release `SHA256SUMS` covers the downloadable ZIP, PDF and prompt. Hashes provide integrity checks, not independent author attestation. Previous releases retain their original assets.

Markdown links are adjusted for GitHub browsing. Root tools and their `scripts/` copies must stay identical; the validation command checks this. The `content/` copies support fixture tests. Historical review records describe the state at their review time; this release supersedes only repository-publication status.

Run `python3 scripts/validate-toolkit.py` before proposing a change. Regenerate checksums for an intentional release and rerun disposable-VM exercises when executable hardening guidance changes. Keep customer evidence and generated snapshots outside Git.
